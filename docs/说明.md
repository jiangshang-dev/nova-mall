# 架构说明
nova-common-core 核心模块，封装一下公共的方法，如工具类、常量类、IpUtil等
nova-common-log 日志模块，封装一下日志注解，在每个接口加日志注解采集接口操作日志，记录IP、请求参数、响应参数、耗时等信息
nova-common-search 搜索模块，封装一下搜索相关的方法，用于首页商品搜索，mysql数据同步到elasticsearch用mq异步方式处理
nova-common-domain 实体模块
nova-common-oss  oss存储模块,已封装好,直接用即可，支持本地文件上传和阿里云oss存储
nova-common-redis redis缓存
nova-common-security 安全认证
nova-common-datasource 数据源模块
nova-common-mq 消息队列 rabbitmq
- producer包 生产者
- consumer包 消费者

文件上传oss配置已经在配置文件配置好oss的accessKey、secretKey、endpoint、bucketName、folder等参数
遵守设计模式，如单例模式、工厂模式、策略模式等，根据实际情况选择合适的模式
遵守SOLID设计原则，如开闭原则、里氏替换原则、依赖倒置原则、接口隔离原则、依赖注入原则等
遵守高内聚低耦合原则，每个模块负责自己的功能，不依赖其他模块的功能

接口层在nova-web模块里面
GlobalExceptionConfig.java  全局异常处理

# 必须规则
1、优先用hutool的工具类
2、必须写清注释
3、接口必须加如下注解：
@Tag(name = "")
@RestController
@AllArgsConstructor
@RequestMapping
@Operation(summary = "账户信息列表")
@Debounce 仅增删改使用
@PreAuthorize 接口加权限
获取当前登录用户封装好了工具类：UserUtil
管理后台前端必须加权限菜单和后端保持一致
CacheService缓存只用工具类
service包必须是接口加impl包实现类

4、sql脚本放在当前项目下的sql目录里面
5、如果写sql语句，只能在mapper xml文件里面写

一切遵守阿里巴巴java开发规范2.0版本，包括数据库sql脚本、代码规范等；
一切遵守spring boot规范，包括注解、配置文件等

# 禁止规则
禁止用fastjson
禁止反向引入依赖，如nova-common-core引入nova-modules里面的所有模块
禁止用@Select注解
禁止用@Insert注解
禁止用@Delete注解
禁止用@Update注解
禁止用JdbcTemplate类
数据库表禁止建外键约束
禁止重复写重复的工具类，优先看有没有现有的工具类，没有再写，如IpUtil等
一切遵守阿里巴巴java开发规范2.0版本，包括数据库sql脚本、代码规范等

前端规则：
前端组件统一使用nova-mall-views \ nova-mall-back里面的组件，和jeecgboot组件保持一致
